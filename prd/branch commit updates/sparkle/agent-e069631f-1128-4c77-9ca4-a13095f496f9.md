Second roborev pass (job 7) on the review-fix commit. Fixed that at the query level, plus four test-robustness findings. The HIGH comment-scoping blocker is unchanged and still needs Erika's decision.

### Detail of changes made:

- **`listSignatures` now returns one row per person (Medium — fixed).** This is the one I caused. `getSignatureCount()` became distinct-by-signer in the previous commit, but `listSignatures` still returned one row per signature row, so on `/signatories` a re-signer renders twice directly beneath a header that counts them once — and the `key` was `signerId + version`, so React wouldn't even flag the collision. Rewrote the query as `selectDistinctOn([signatures.signerId])` ordered by `signerId, signedAt DESC`, wrapped in an outer query that applies the newest-first ordering and the page window (DISTINCT ON requires its own ORDER BY to lead with the distinct column, so the two orderings can't share one query). Test written first — failed with `['Alice','Bob','Alice']` — then fixed.
- **`/signers` post-fetch dedupe removed (Medium — same finding).** It deduped only *within* the fetched page, so a 100-row page could render fewer than 100 people while the offset still advanced by 100 — silently skipping signers between pages. Now unnecessary: the query returns 100 people for a 100-row page.
- **`/signers` header count corrected (Medium — same finding, pre-existing).** It used `getSignerCount()`, which counts rows in `signers` — including admin-added non-signers created by `createNonSigner` in `src/server/actions/admin.ts:338`, who have a signer row but no signature. On a page headed "Verified signers" listing only people who signed, that over-reports. Switched to `getSignatureCount()`. All three surfaces (`/`, `/signatories`, `/signers`) now report the same number.
- **`getSignatureNumber` regression guard (Low — fixed).** The earlier test used one signer and identical timestamps, so it couldn't detect whether step 1 picks the signer's *earliest* signature — flipping `asc` to `desc` would have passed while every re-signer's public "Signer #N" jumped. Added a two-signer case with distinct timestamps: A signs v1 first, B signs v1 second, A re-signs v2 last; asserts A is #1 and B is #2. It passed on the first run, confirming the existing `asc` ordering is correct — it's a guard, not a fix.
- **`previousVersion()` bounds check (Low — fixed).** Returned `history[idx - 1]` unguarded, so a first-ever version (idx 0) would die with `Cannot read properties of undefined` instead of a readable skip. Now returns `null` and the carry-over test early-returns.
- **Exemption-list dereference (Low — fixed).** The honesty test did `findIndex` then dereferenced without checking `-1`, so a renumbered article failed as a `TypeError` reading like a broken test rather than "the exemption list is stale." Now asserts the index with a message naming the fix.
- **Markdown-in-resources guard (Low — fixed).** The four files were de-emphasized by hand with nothing stopping the next author from reintroducing markdown into a renderer that emits plain text nodes — exactly the drift class the rest of this branch added tests for. New `describe("resource pages")` block checks every file in `content/resources/` for emphasis, headings, links, list items, and backticks, naming the offending syntax in the failure message. All 33 files pass.
- **Prefix test narrowed (Low — fixed).** It was fully implied by the new exact `body + pullQuote` check for the seven non-exempt articles. Now scoped to the four exempted ones, where it's their only coverage, with a comment saying why.
