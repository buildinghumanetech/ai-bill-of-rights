### Potential concerns to address:

- **Signatures do not carry forward, by design.** `getMySignatureStatus(VERSION)` filters signatures by exact version string. Everyone who signed v0.0.1 now reads as `not-signed` for v0.1.0 and will be shown the sign form again. This is arguably the correct semantic for a new version, but it means the public signature count for the *current* version starts at zero until people re-sign. Decide whether the homepage `<SignatureCount />` should count all versions or just the current one, and whether existing signers get a "re-affirm" flow rather than a cold sign form.
- **No signer notification exists.** `SignModal` collects a `notificationPreference` of `major` / `minor` / `none`, but nothing consumes it. Publishing 0.1.0 is exactly the "minor revision" event that preference promised, and **no email will go out**. Either build that send or accept that the preference is currently decorative.
- **The two content sources are still duplicated**, just now tested. `HomepageArticles.tsx` holds a second copy of the article text. The new test catches divergence but the real fix is deriving the homepage array from the parsed markdown — blocked on the markdown parser not emitting the `pullQuote` / `connects` metadata the homepage needs. Consider moving pull quotes and pill slugs into the spec.json and rendering from there.
- **`postbuild` runs `sync-versions`.** The new version row only lands in the DB when `tsx scripts/sync-versions.ts` runs against a real `DATABASE_URL`. On Vercel that happens automatically via `postbuild`; for any manual/preview environment it must be run by hand or `/v/0.1.0` will 404 and `getCurrentVersion()` will keep returning 0.0.1.
- **Article 10 and 11 body copy is a first draft** written to match the house voice of Articles 1–9 and expanded from the two one-line summaries in the source mock. It has not been through editorial review. `prohibited_behaviors`, `required_behaviors`, and `test_conditions` are still empty for all 11 principles.
- **`bumpPatch()` now yields `0.1.1`** as the "proposed" version label on `/proposed`. Since 0.1.0 was itself a minor bump adding articles, the next proposed round may want to be `0.2.0`; `bumpPatch` in `src/lib/homepage/load-tab-data.ts` can only ever bump the patch digit.
