### Detail of changes made:

- **`PillCategory` is a discriminated union, not a `matches` callback.** The previous commit
  added an optional `slugs` field so the overlap test could enumerate a rule's domain — but
  nothing *required* it. A future category written the way `us-law` was written one commit
  earlier (`matches: (s) => MY_SET.has(s)`) would compile, contribute nothing to the test's
  domain, and escape the overlap check silently. The claim that new list-based categories
  were "covered automatically" was therefore wrong; the burden had just moved from the test
  file to the category literal, with no failing test to prompt it.

  The shape is now `{ id, className } & ({ prefixes } | { slugs } | { catchAll })`, with
  matching derived by `categoryMatches`. A list-based rule cannot be expressed without
  declaring its domain. **Verified negatively**, not assumed — a probe file asserting both
  bad shapes fails to typecheck:
  - `{ id, className, matches: (s) => SET.has(s) }` → TS2352, even with an `as` cast
  - `{ id, className }` with no rule at all → TS2322
- **`pillCategory` now returns `Readonly<PillCategory>`.** It was returning the mutable
  alias while reading from a `readonly Readonly<PillCategory>[]`; TypeScript ignores
  `readonly` property modifiers in assignability, so `pillCategory("coppa").className = …`
  typechecked and would mutate the shared module literal for every later render. That was
  the same mutation-through-export hole the previous commit closed on `US_LAW_SLUGS` and
  `PILL_CATEGORIES`, left open on the one accessor everything calls. (These guards are
  compile-time only — nothing is frozen at runtime.)
- **Guarded the suite's central assertion.** `expect(interactivePills).toEqual(staticPills)`
  is the test that holds the two tabs identical, and it was the last one with no
  non-emptiness check. Empty arrays compare equal as quietly as an empty loop body runs; the
  previous round added guards only to tests that *iterate*, which missed this shape.
- **Corrected a stale comment** claiming the domain is derived "rather than importing
  `US_LAW_SLUGS` by name" on the line immediately above an import of `US_LAW_SLUGS` by name.
  The assertion is a reasonable bridge — it fails if someone drops `slugs` from the us-law
  entry — but the comment described code that wasn't there.
