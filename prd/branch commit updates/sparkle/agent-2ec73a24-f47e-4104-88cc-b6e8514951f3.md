### Second roborev pass (job 133) — three low findings, two applied

- **`classesOf` now throws instead of returning `""`** when the tag is absent. The
  Proposed-variant `not.toContain("text-center")` is the suite's only guard that the step
  grid stays left-aligned, and it was exactly the assertion that would have passed
  vacuously if the root `<section>` were ever renamed to a `<div>`. Also anchored it with
  a positive `toContain("rounded-xl")` on the same class list.
- **Delimited the tag name** in the `classesOf` pattern with `(?=[\s>])`. Undelimited,
  `classesOf(html, "p")` matched `<path>`, `<pre>` and `<param>` equally well — an inline
  SVG icon added to the heading would have been enough to silently retarget the assertion
  at the wrong element's class list.
- **Not applied:** the finding that `render()` and `text()` render the same tree twice.
  It is real but pre-existing — the reviewer notes the sibling test at `:157` has the same
  shape — so fixing it only in the new cases would make the file inconsistent. It costs
  one extra render of a static component and cannot change a verdict. Left for a
  suite-wide cleanup that promotes the tag-stripping half of `text` into its own helper.

### Third roborev pass (job 134) — two low findings, both applied as one change

Both findings pointed at the same soft spot, so one change closes them:

- **`classesOf` now asserts uniqueness**, not first-match: it collects all matches and
  throws unless there is exactly one. The previous throw only fired when *no* element of
  that tag carried a class — the pattern skips unclassed opening tags and advances — so
  inserting a second classed `<section>`, or a classed `<p>` above the body paragraph,
  would still have found *a* match and silently retargeted the assertion. This also
  corrects the "first-match" framing in the previous entry's concerns: the real semantics
  were "first *classed* element of that tag", which is now "the only one, or it throws".
- **Dropped the `toContain("rounded-xl")` anchor** added in the pass before. With the
  uniqueness throw in place it guarded nothing the throw did not already cover, and it
  added a false-failure surface: bumping the corner radius to `rounded-2xl` would have
  broken a test named "keeps its heading and step list intact and left-aligned", pointing
  at a class nobody had changed the alignment of. The likely repair for that is to edit
  the string, which is how a guard erodes.

### Fourth roborev pass (job 135) — two low findings, both applied

- **The uniqueness rule was already binding, not hypothetical.** The previous entry filed
  "adding a second classed `<p>` makes the assertion throw" as a *future* risk; the element
  exists today. `FeedbackInvite` renders a second classed `<p>` (the count line) whenever
  `commentCount > 0`, so `classesOf(render(current(12)), "p")` threw `found 2`. The
  centering test passed only because it happened to use the `current(0)` fixture — the
  helper was unusable against the populated state, which is the state the banner is
  normally in. `classesOf` now takes an optional discriminator
  (`classesOf(html, "p", "max-w-3xl")`), and the centering test is an `it.each([0, 12])`
  so it runs against both states. 918 tests now, up from 917.
- **Corrected the helper's doc comment**, which claimed "an inserted sibling fails the
  test" when the pattern requires `\sclass="…"` and so only counts *classed* elements. An
  unclassed wrapper still slips past. Defensible behavior, but the header read as a
  stronger invariant than the code provides — the same over-reading that produced the
  earlier "first-match" framing. Now says so explicitly.

### Fifth roborev pass (job 136) — three low findings, all applied

- **The discriminator match is now an exact class-token comparison**
  (`c.split(/\s+/).includes(d)`) instead of a substring `includes`. As a substring,
  `"max-w-3xl"` also accepted `sm:max-w-3xl` — reintroducing one layer down exactly the
  imprecision the `(?=[\s>])` tag lookahead was added to prevent.
- **The `count: 12` case now asserts something only it can see.** As written it was
  byte-identical to the `count: 0` case: the only markup that differs is the count `<p>`,
  and the `max-w-3xl` discriminator filtered that out before either assertion ran. So the
  new parameter exercised the *helper* rather than the component. It now also checks the
  count line's own class list, which exists only in the populated render.
- **Doc comment corrected again**, in a new place. It still claimed "an inserted classed
  sibling fails the test", which stopped being true the moment the discriminator was added:
  the `.filter` runs before the count, so a second classed `<p>` *without* the
  discriminator passes unnoticed. Both escape hatches (unclassed elements, and
  non-discriminator siblings) are now stated plainly.

### Sixth roborev pass (job 138) — two low findings, both applied. This one found a real hole.

- **`classesOf` now returns class *tokens*, not the raw class string.** Previous rounds made
  the discriminator an exact token match but left every *assertion* a substring `toContain`
  over the string — which is what the tests actually check. `toContain("text-center")` was
  satisfied by `sm:text-center`, `toContain("mx-auto")` by `sm:mx-auto`, `toContain("mt-2")`
  by `mt-20`. **A banner centered on desktop and broken on mobile passed the whole suite.**
  Returning an array makes every existing `toContain` / `not.toContain` exact membership,
  with no call-site changes.
  - *Verified by mutation, not by inspection:* changing `text-center` → `sm:text-center` in
    `FeedbackInvite.tsx` now fails both centering cases. It passed before this change.
- **Moved the count line's styling assertions out of the centering test** and into
  `"mentions the comment count only when there is one"`, where they belong. Asserting
  `text-zinc-600` / `mt-2` inside a test named for centering re-created exactly the
  false-failure surface that got the `rounded-xl` anchor retired two commits earlier: a
  palette tweak would have failed a centering test with a message about colors. The
  `it.each([0, 12])` stays, but its honest claim is now "centering does not depend on the
  count" rather than a smuggled-in check of unrelated markup.
