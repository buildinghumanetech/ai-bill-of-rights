  now asserts against the button's own class list (no `bg-blue-600`, no `rounded-full`).
- **`tests/app/signature-momentum.test.tsx`** — the "without shrinking the row" test never
  asserted the row length, so its name was a claim the body did not make (Katherine's
  absence is guaranteed by the cap regardless of filtering). Added the `<li>` count. Also
  widened the counting regex from `/<li /g` to `/<li[ >]/g`: the old one only matched list
  items carrying attributes, so an attribute-free `<li>` would have counted as zero and
  read as a cap violation rather than a markup change.

## Progress Update as of [2026-07-28 10:30 Pacific]
*(Most recent updates at top)*

### Summary of changes since last update

First entry on this branch. Two homepage presentation fixes: the "Recently signed by"
pill row now shows three signers instead of six so it sits on one line, and the blue
"This is a living document" banner above the document tabs was shortened, de-em-dashed,
centered, and had its filled blue button demoted to a text link. Added the branch's
first coverage for `FeedbackInvite`, which had none.

### Detail of changes made:

- **`src/components/SignatureMomentum.tsx`** — introduced `RECENT_SIGNER_CHIPS = 3`
  (module-level const, near `MomentumSigner`) and used it for the `.slice()` in
  `SignatureMomentumPanel` that previously hardcoded `6`. Layout was already
  `flex flex-wrap justify-center`, so no class changes were needed: three chips fit
  one line at desktop width and still wrap on a narrow phone rather than clipping names.
- **`src/app/page.tsx`** — `loadSignerSample` intentionally still fetches
  `listSignatures(null, { limit: 6 })`. The over-pull is not a leftover: the panel
  filters out signers whose `displayName` is blank, so fetching exactly three would let
  two anonymous signers collapse the row to a single chip. Added a doc comment saying
  this, because the 6-vs-3 mismatch now reads like a bug to anyone scanning it.
- **`src/components/FeedbackInvite.tsx`**, `variant === "current"`:
  - Heading `This is a living document — you can change it.` →
    `This is a living document. You can change it.`
  - Body cut from five sentences to two. Dropped the "voted up or down" and
    "not a reason to walk away" beats.
  - `text-center` added to the `<section>`; the paragraph gained `mx-auto` alongside its
    existing `max-w-3xl`. Without `mx-auto` a width-capped paragraph stays pinned to the
    left edge of a centered box — this is the non-obvious half of "center the box".
  - The filled `rounded-full bg-blue-600` button became an underlined blue text link.
    It is still a `<button>`, not an `<a>`: it calls `onOpenDraft` to switch tabs in
    place rather than navigating, so link *semantics* would be wrong even though link
    *styling* is what was wanted.
  - Link text is new (`Mark up the v{proposedVersion} draft →`) because both prior
    strings were removed by request — the old button label and the
    `No comments yet — yours would be the first.` empty state.
  - The comment count line now renders only when `commentCount > 0`, as
    `{n} comments already.` At zero the box shows nothing there.
- **`src/components/FeedbackInvite.tsx`**, `variant === "proposed"` — em dashes only, by
  request. Heading now `You're in the draft. This is where feedback happens.` and
  `STEPS[0].detail` now `Drag across a sentence. On a phone, press and hold.` Its
  `sm:grid-cols-3` numbered step list is deliberately left un-centered.
- **`tests/app/feedback-invite.test.tsx`** (new) — `FeedbackInvite` had zero coverage.
  Asserts no U+2014 in either variant, `text-center` present on Current and absent on
  Proposed, `mx-auto` + `max-w-3xl` both on the paragraph's class list, the new link text,
  absence of the two removed strings, and the count line's presence/absence at 12 vs 0.
- **`tests/app/signature-momentum.test.tsx`** — grew the shared `sample` fixture from 3 to
  5 named signers. This mattered: at exactly 3 the new cap assertion would have passed
  vacuously against the old `.slice(0, 6)`. Added a case asserting exactly three `<li>`
  render and the 4th/5th names do not, plus one covering a blank-display-name signer
  being filtered without shrinking the row.

### Potential concerns to address:

- **The 6-fetch / 3-render split is a real trap.** It is commented on both sides now, but
  anyone "tidying" `loadSignerSample` down to `limit: 3` will silently reintroduce the
  short-row bug, and no test catches it — the panel test passes a fixture directly and
  never exercises the query. A test over `loadSignerSample` would need DB mocking.
- **`pnpm build` cannot complete in a bare worktree.** There is no `.env.local`, so the
  export step dies on `/_not-found` with `@clerk/clerk-react: Missing publishableKey`,
  preceded by `DATABASE_URL is not set`. Compilation itself succeeds
  (`✓ Compiled successfully`), and `tsc --noEmit` is clean, so this is environment-only —
  but it means a local `pnpm build` is not a usable gate here.
- **The signer chips could not be verified in a live browser** for the same reason: with
  no database the count is 0 and the sample is empty, so the "Recently signed by" block
  does not render locally at all. Its three-chip behavior rests entirely on the unit
  tests. Worth an eyeball on a preview deploy.
- **Chips are gated on `RAW_COUNT_THRESHOLD`** (5000, overridable via
  `NEXT_PUBLIC_SIGNATURE_COUNT_THRESHOLD`). Above it, `SignatureMomentumPanel` early-returns
  the "scale" branch and the recent-signers row disappears entirely — the three-signer
  change is only ever visible below that threshold.
- **Em dashes remain elsewhere on the homepage** and were left alone as out of scope:
  the hero line in `src/app/page.tsx`, the `Version X — a living document` footer eyebrow,
  and its twin in `src/app/v/[version]/page.tsx` (which uses `&mdash;`). If the intent is
  a site-wide dash purge, those are the next targets.
