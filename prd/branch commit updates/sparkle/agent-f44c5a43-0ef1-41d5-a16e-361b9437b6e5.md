### Summary of changes since last update

Triaged the roborev review of 476b7c1 (job 40, six findings). Fixed the two Medium
findings and two of the four Low ones; verified one Low finding was factually wrong and
dismissed it. The important one: the root `openGraph.url` added in the previous commit
was being shallow-inherited by every child route, so `/about` and `/resources/[slug]`
were advertising themselves as the homepage — a regression this branch introduced.

### Detail of changes made:

- **Removed `url` from the root `openGraph`** (`src/lib/site-metadata.ts`). Next merges
  metadata shallowly: a route defining no `openGraph` inherits the parent's entire object.
  Confirmed empirically before fixing — `curl /about` on the previous build returned
  `og:url = https://ai-for-people.org` plus the homepage's og:title and og:description.
  Scrapers prefer `og:url` as the canonical target, so sharing `/about` produced a card
  pointing at the homepage. `metadataBase` already handles canonical resolution, so
  nothing is lost by dropping it. Guarded by a new test asserting the root `openGraph`
  has no absolute `url`.
- **Gave `/about` and `/resources/[slug]` their own `openGraph`/`twitter` blocks**, mirroring
  their existing titles/descriptions. These were the only two routes that set a custom
  title but no OG block; `/signatories/[id]` already had one. Routes with no metadata at
  all (`/signers`, `/proposed`, `/why`) legitimately inherit the root's.
- **Hardened `getSiteUrl()`** against a malformed `NEXT_PUBLIC_SITE_URL`. It now parses in
  a `try`, warns, and falls back to `PRODUCTION_ORIGIN` on failure. This matters because
  the value reaches `new URL()` at module scope via `export const metadata =
  buildRootMetadata()` in the root layout — a scheme-less value like `ai-for-people.org`
  throws `TypeError` there and takes down every route including the build. Other readers
  of the variable only string-concat it, so they degraded to a broken link rather than an
  outage; this commit keeps that property.
- **Added a `VERCEL_URL` fallback** ahead of the hardcoded production origin, so preview
  deploys (which get no per-branch `NEXT_PUBLIC_SITE_URL`) advertise themselves instead of
  production. Also normalized away any trailing slash.
- **Replaced the weak description assertion.** The old
  `expect(SITE_DESCRIPTION.length).toBeGreaterThan(SITE_TAGLINE.length)` passed for any
  longer string. Now an upper bound of 160 chars, the SERP truncation window. (Roborev
  claimed the description was ~200 chars and needed trimming — it is actually 151, so it
  already fits and was left alone.)
- **Softened the module doc comment.** It claimed to be the "single source of truth for how
  the site names itself" while six other files still hardcode "AI Bill of Rights". Rather
  than refactor six files inside a packaging change, the comment now names those call
  sites so a future rename knows where to look.
- Test count for `tests/lib/site-metadata.test.ts` went 8 → 13.

## Progress Update as of [2026-07-25 08:45 Pacific]

### Summary of changes since last update

First entry on this branch. Addressed feedback that the title "The AI Bill of Rights"
reads as *rights belonging to AI* until you reach the articles. Rather than renaming the
document, this change makes the title never appear without its disambiguating tagline:
added `src/lib/site-metadata.ts` as the single source of truth for the site's name,
tagline, and description, wired it into the root metadata (including previously-absent
OpenGraph/Twitter tags), and surfaced the tagline as a hero eyebrow on the homepage.

### Detail of changes made:

- **New `src/lib/site-metadata.ts`.** Exports `SITE_NAME` ("The AI Bill of Rights"),
  `SITE_TAGLINE` ("A People's Demand for Human-Centered AI"), `SITE_TITLE` (the two
  joined with an em dash), `SITE_DESCRIPTION`, `getSiteUrl()`, and `buildRootMetadata()`.
  The point of the module is that the tagline and the name live in one place, so the
  `<title>`, the share cards, and the hero cannot drift apart. The module is intentionally
  free of Next/Clerk/DB imports so it is unit-testable in the `node` vitest environment.
- **`src/app/layout.tsx`** now does `export const metadata: Metadata = buildRootMetadata()`
  in place of the inline object. Previously `title` was the bare "AI Bill of Rights" and
  there were no `openGraph`/`twitter` blocks at all, so link previews in Slack/iMessage/X
  fell back to whatever scrapers inferred.
- **`metadataBase` is now set** (from `NEXT_PUBLIC_SITE_URL`, falling back to
  `https://ai-for-people.org` — the same fallback `src/server/actions/invite.ts` and
  `src/app/signatories/[id]/page.tsx` already use). Side benefit: the relative OG image
  URL on the signer profile route (`/api/og/signer/[id]`) now resolves against a real
  origin instead of Next's inferred one.
- **Deliberately did NOT add a root `title.template`.** Child routes (`/about`,
  `/signatories/[id]`) already set their own absolute titles; a template would have
  produced "About — AI Bill of Rights — The AI Bill of Rights". Keeping the root title as
  a plain default keeps the blast radius to the homepage.
- **`src/app/page.tsx`** renders `SITE_TAGLINE` as a small-caps eyebrow above the `<h1>`,
  and the `<h1>` now interpolates `SITE_NAME` instead of hardcoding the string. Eyebrow
  styling (`text-sm font-semibold uppercase tracking-[0.2em] text-zinc-500`) mirrors the
  existing kicker on the about page, one step larger for legibility.
- **New `tests/lib/site-metadata.test.ts`** (8 tests). The load-bearing one is "never lets
  the bare name travel alone on a title surface", which asserts the tagline is present in
  the document title, `og:title`, and `twitter:title`. Verified it actually guards the
  regression by temporarily setting `SITE_TITLE = SITE_NAME` — 2 tests failed, then passed
  again on restore.

### Potential concerns to address:

- **No default OG image.** `twitter:card` is `summary` (small square) rather than
  `summary_large_image`, because the site has no root share image — `src/app/api/og/` only
  has the per-signer route. Since sharing the link is the main distribution path, a
  site-level OG image is the highest-value follow-up; the pattern to copy is
  `src/app/api/og/signer/[id]/route.tsx`. Once it exists, switch the card type.
- **The tagline now lives in two places conceptually.** `SITE_TAGLINE` in
  `src/lib/site-metadata.ts` and the preamble line in
  `content/bill-of-rights/v0.0.1.md:11` ("A People's Demand for Human-Centered AI.", with
  a trailing period and a `{#preamble-s-1}` anchor). They are not linked in code. If the
  preamble subtitle is ever reworded, the site chrome will silently keep the old wording.
  Parsing it out of the markdown was considered and rejected as more fragile than the
  duplication, but it is worth knowing.
- **The naming question is still open.** This change was explicitly scoped to packaging,
  not a rename. "Your AI Bill of Rights" / "The People's AI Bill of Rights" remain on the
  table; if either is adopted, `SITE_NAME` is the one place to change it, though the
  `<h1>` copy, the about-page back-link, and the signer-page metadata string
  ("… signed the AI Bill of Rights") would also want a look.
- **Local builds need env vars.** Anyone running `next build` in a fresh worktree without
  `.env.local` will hit the Clerk prerender failure described above. Not introduced here,
  but it makes "does the build pass" a non-obvious check.
