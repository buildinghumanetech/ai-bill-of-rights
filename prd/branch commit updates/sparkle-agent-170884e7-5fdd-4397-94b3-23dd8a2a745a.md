### Summary of changes since last update

Closed out roborev job 95. The headline fix: `<ShareSignature />` — the share box on the
signer's own public page — was still hand-rolling its share *pitch* even after href
construction had been consolidated onto `shareHrefs`, so it never passed `whyISigned` and
silently dropped the signer's own statement from the share surface a signer is most likely
to use. It now goes through `buildShareText`, which also puts its X copy under
`truncateToWeight`/`X_TEXT_BUDGET` for the first time. Alongside that: three test/API
hygiene fixes roborev flagged (a TDZ trap in the invite test's `vi.mock` factory, a leaking
`process.env` write, and an X-href assertion that only pinned half the drift it documented),
plus a rename of `signInvitation`'s misleading `siteUrl` parameter.

### Detail of changes made:

- **`src/components/ShareSignature.tsx`** — deleted the local `shareText` constant (the
  fourth copy of the pitch, opening `"I signed…"` and closing with a full stop, vs
  `GENERIC_SHARE_TEXT`'s `"I just signed…"` / colon) and its stale "not one owner's to
  move" comment. The `shareHrefs` resolver is now
  `text: (channel) => buildShareText({ channel, whyISigned })`. Added an optional
  `whyISigned?: string | null` to `Props`.
  - Three things this fixes at once: the two surfaces stop sending different copy for the
    same action; the X variant is finally measured against X's *weighted* limit rather than
    hoped to fit; and the signer's own sentence actually rides along. The last is the point
    of the "why I signed" feature — a personal sentence converts better than boilerplate —
    and it was being defeated exactly where it should work hardest.
  - `share-text.ts` is a pure module (no drizzle/db/server imports) precisely so a
    `"use client"` component can import it; `SignModal.tsx` already does the same.

- **`src/app/signatories/[id]/page.tsx`** — passes `whyISigned` (already computed on the
  page via `normalizeWhyISigned`, line ~81) down to `<ShareSignature />`. No new query, no
  new normalisation: the page had the value in hand and simply wasn't handing it over.

- **`src/lib/email/templates.ts`** — `signInvitation`'s `siteUrl` param renamed to
  `readItUrl`, with a docblock stating that BOTH URLs must arrive already tagged with
  `?ref=`/`?via=invite`. The invariant lived entirely at the one call site while the
  signature still said "pass the bare origin" — which is exactly what the pre-attribution
  code did. The name is now a signal instead of a trap. Call site updated in
  `src/server/actions/invite.ts` (`readItUrl: homeShareUrl(...)`) and in
  `tests/lib/email.share-attribution.test.ts`.

- **`tests/server/invite.share-attribution.test.ts`** — two fixes:
  - `dbStub` moved *inside* the existing `vi.hoisted` block (as `state.db`), and the
    `vi.mock("@/lib/db")` factory switched to the getter form the sibling
    `signer-deletion.referrals.test.ts` uses. The old form closed over a module-scope
    `const` declared below the hoisted `vi.mock` and the hoisted `import` of the action.
    It was harmless only because nothing in the graph *statically* imports `@/lib/db`
    today (the `Module._load` patch is what actually intercepts the lazy `require`) — the
    day `invite.ts` swaps that `require` for a normal `import`, the factory fires during
    hoisted evaluation and throws `ReferenceError: Cannot access 'dbStub' before
    initialization` instead of mocking. Verified: see mutation notes below.
  - `process.env.NEXT_PUBLIC_SITE_URL = SITE_URL` in `beforeEach` replaced with
    `vi.stubEnv(...)` plus `vi.unstubAllEnvs()` in a new `afterAll`. `process.env` is one
    object shared by every file in a Vitest worker; the unrestored write was the same
    cross-file-state leak class as the jsdom clipboard stub fixed earlier on this branch,
    and it made the file's otherwise-symmetric hook discipline (`beforeAll`/`afterAll`
    around the `Module._load` patch) inconsistent with itself.

- **`tests/app/share-signature.share-links.test.tsx`** — the file's docblock claimed the
  drift was "the X href stuffed the share URL inside `text=` with no `&url=` param", but
  only the `&url=` half was ever asserted. Re-inlining the URL into `text=` while keeping
  `&url=` (posting the link twice), or shipping an empty `text=` (a bare link with no
  pitch), both stayed green. Added `keeps a real pitch in X's text=, with the URL only in
  &url=`, which pins non-empty text AND the absence of the URL from it. Also introduced a
  `renderHrefs(whyISigned?)` helper and a `param(href, name)` accessor that returns `null`
  for a missing param rather than crashing on a non-null assertion, so a missing `&url=`
  now fails as an assertion instead of a `TypeError`.
  - Added `describe("ShareSignature share copy carries the signer's own statement")` with
    two cases: the statement appears in both the X `text=` and the mailto `body=` (LinkedIn
    carries no text by design), and the X post stays within `X_POST_LIMIT` measured by
    `xPostWeight` for three statements including 198 code units of Japanese and 200 emoji —
    inputs where `.length` and X's weighted count disagree by 2x.

### Verification performed (mutation testing, not just a green run)

Four tests shipped earlier on this branch that could not fail, so each new assertion was
mutated red before being trusted:

1. Changed the resolver to `buildShareText({ channel })` (i.e. reintroduced the exact bug):
   `leads every channel's copy with the signer's sentence` FAILED —
   `expected 'I just signed the AI Bill of Rights — …' to contain 'My daughter will grow up…'`.
2. Routed the X channel through the untruncated variant
   (`channel: channel === "x" ? "linkedin" : channel`), bypassing `truncateToWeight`:
   `keeps the X post inside X's weighted limit` FAILED — `expected 545 to be less than or
   equal to 280`. A separate throwaway probe confirmed BOTH heavy cases (Japanese and
   emoji) are individually over budget without the truncation path and inside it with —
   the loop short-circuits at the first failure, so this was checked explicitly rather
   than assumed.
3. Appended the URL to the text (`${buildShareText(...)} ${signerShareUrl(...)}`), keeping
   `&url=` intact: the NEW `keeps a real pitch in X's text=` test FAILED while the OLD
   `puts the share URL in X's own &url= param` test still PASSED — confirming roborev's
   read that the original assertion survived the regression it documented.
4. TDZ trap: a throwaway probe with a module-scope `const dbStub`, a `vi.mock` factory
   closing over it, and a static `import { db } from "@/lib/db"` reproduced
   `ReferenceError: Cannot access 'dbStub' before initialization` — the failure mode the
   hoisted-state fix removes.
5. Env restore: a throwaway probe stubbing in `beforeEach` across two tests then asserting
   in `afterAll` confirmed `vi.unstubAllEnvs()` returns the variable to its original value
   (including the "was never set" case).
